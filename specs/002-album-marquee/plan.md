# Implementation Plan: Album Marquee — Music Section

**Branch**: `feature/add-speckit` | **Date**: 2026-05-19 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/002-album-marquee/spec.md`

## Summary

Replace the CSS Grid album layout in `SpotifyPlaylist.astro` with a single-row, continuously scrolling marquee. The marquee uses a pure CSS `@keyframes` animation — no new dependencies, no JavaScript. Album tiles are rendered twice (original set + `aria-hidden` duplicate) so the loop is seamless. Hover pauses the animation via CSS `:hover`. The individual tile link logic (`songUrl || PLAYLIST_URL`) is already implemented and requires no changes.

## Technical Context

**Language/Version**: TypeScript / Astro 5 (SSR via `@astrojs/vercel`)
**Primary Dependencies**: No new dependencies.
**Storage**: N/A — no data layer changes.
**Testing**: None (Principle V — visual-only change; no data transformation).
**Target Platform**: Vercel SSR (unchanged).
**Performance Goals**: CSS `transform` animation is GPU-accelerated; no additional network requests; no JS execution cost.
**Constraints**: CSS `@keyframes` for animation (GSAP deviation justified — see Constitution Check); SCSS for all styling; no JavaScript.
**Scale/Scope**: Tiles are duplicated in SSR output (~30–80 unique tracks → ~60–160 `<li>` elements). Negligible HTML size increase.

## Constitution Check

| Principle | Status | Notes |
| :--- | :--- | :--- |
| I — Guest Experience First | ✅ Pass | Animated marquee enhances the music section; purely additive guest value |
| II — Privacy & Exclusivity | ✅ Pass | No guest data; no new API calls; purely a visual change |
| III — Native Web Components, Minimal JS | ✅ Pass | CSS-only animation; no JavaScript added; no new runtime dependencies |
| IV — Design Integrity (GSAP patterns) | ⚠️ Justified deviation | A marquee is continuous and non-scroll-triggered — GSAP ScrollTrigger requires a scroll position to drive, which is the wrong model here. | V — Simplicity & YAGNI | ✅ Pass | Two files changed; no new abstractions; tile duplication is the minimal correct approach for a seamless CSS loop |

### File Responsibilities

**`src/styles/components/music.scss`**

Remove `.album-grid` CSS Grid rules. Add:
- `.album-marquee` — `overflow: hidden` outer container; `:hover` selector sets `animation-play-state: paused` on the track child
- `.album-marquee__track` — `display: flex; width: max-content; gap: <gutter>; animation: marquee-scroll 40s linear infinite; list-style: none; margin: 0; padding: 0`
- `@keyframes marquee-scroll` — `from { transform: translateX(0) }` → `to { transform: translateX(-50%) }` (seamless because track is double the visible tile set width)
- `.album-tile` — retain existing styles; add `flex-shrink: 0; width: 170px` (fixed width needed in flex row)

**`src/components/homepage/SpotifyPlaylist.astro`**

- Change `<ul class="album-grid">` to `<div class="album-marquee"><ul class="album-marquee__track">`
- Render `songs.map(...)` once for the visible set
- Render `songs.map(...)` a second time with `aria-hidden="true"` on each duplicate `<li>` (screen readers see content once only)
- Close with `</ul></div>`
- All tile internals (link, img fallback, song title, artist text) are unchanged

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
| :--- | :--- | :--- |
| CSS `@keyframes` instead of GSAP ScrollTrigger | Marquee is continuous and not scroll-driven | GSAP ScrollTrigger needs scroll position to animate; a marquee runs independently. Using `gsap.to()` with `repeat: -1` would be more code for the same visual result. |
| Tile duplication in SSR output | `translateX(-50%)` seamless loop requires track width = 2× visible tile set | JS-based DOM cloning at runtime would require client JavaScript, violating Principle III. CSS-only duplication adds trivial HTML weight with zero JS cost. |
